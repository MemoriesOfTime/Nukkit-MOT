# Nukkit-MOT block-palette files (DataConvert output)

Read this before touching `runtime_block_states_*.dat`, `vanilla_palette_*.nbt`,
`block_palette_*.nbt` or `canonical_block_states_*.nbt`, or anything under a
[DataConvert](https://github.com/MemoriesOfTime/DataConvert) checkout.
The authoritative manual for the
converter is that repository's `CLAUDE.md` (Chinese, detailed) plus
`docs/converter-reference.md`; this file only covers what matters when
you read or write those NBT files directly with `nbt_tool.py`.

Paths in the recipes below are relative to the Nukkit-MOT repository root; `$DC`
is a [DataConvert](https://github.com/MemoriesOfTime/DataConvert) checkout.

Downloads must be cached inside this skill, never in DataConvert's own `cache/`:

```bash
CACHE="$(pwd)/.agents/skills/minecraft-nbt/.cache/dataconvert"   # run from the Nukkit-MOT root
```

The override is required because `ExternalData` resolves a relative cache dir against
the JVM working directory (the DataConvert root after `cd "$DC"`). `.cache/` is
Git-ignored by `/.agents/skills/**/.cache/`. Pass `-Ddataconvert.cache.dir="$CACHE"`
on every recipe that may download; with a local `nukkitmot.dir`/`bindata.dir` checkout
nothing is downloaded and the flag is inert.

## File families (all verified with `nbt_tool.py info`)

| path (under `src/main/resources/` of DataConvert) | format | shape |
|---|---|---|
| `Target_Data/runtime_block_states_[netease_]XXX.dat` | gzip, big-endian, disk | **List root** of flat entries `{name, id:int, data:short, runtimeId:int, version:int, states:{...}[, stateOverload:byte]}` — Nukkit-MOT's own format, both input and output. List order is *not* palette order. |
| `Target_Data/vanilla_palette_[netease_]XXX.nbt` | gzip, big-endian, disk | compound `{blocks:[{name, version, states}]}` — what the server downloads into `bin/`; index = runtimeId |
| `CB_Data/block_palette_XXX.nbt` | gzip, big-endian | `{blocks:[{block_id, name, name_hash:Long, network_id, states, version}]}` (CloudburstMC/Data) |
| `NetEase_Data/block_palette_XXX.nbt` | gzip or raw, BE or LE — DataConvert probes all four (`Utils.java` 126–141) | `{blocks:[{name, version, states}]}` |
| `NetEase_Data/runtime_block_states_XXX.dat` | gzip, big-endian | **List root** of wrapped entries `{block:{name, states}}` (source data, no runtimeIds) |
| `PMMP_Data/canonical_block_states_XXX.nbt` (≥419) | **network VarInt, raw, multi-root** (7k–15k roots) | each root `{name, states, version}` |
| `PMMP_Data/required_block_states_XXX.nbt` (≤407) | network VarInt, raw | single **List root** of `{block:{name, states, version}, id:short}` |
| `cache/runtime_block_states_*.dat` | gzip BE | downloaded copies of Nukkit-MOT dats; the recipes here relocate this dir to `.cache/dataconvert/` (see above) |

XXX is a Bedrock **protocol version** (388 … 1001, then 2168/2193/2225 for the
new numbering), not a game version.

## Invariants you must not break

1. **runtimeId is an index.** Every entry's `runtimeId` in a `runtime_block_states`
   dat must equal the position of the identical block state inside the matching
   `vanilla_palette_XXX.nbt`. Misalignment fails *silently* on the server (wrong
   blocks rendered). Never renumber by hand; after any edit run the alignment gate:
   ```bash
   CACHE="$(pwd)/.agents/skills/minecraft-nbt/.cache/dataconvert"   # define before cd; absolute
   cd /path/to/DataConvert   # https://github.com/MemoriesOfTime/DataConvert
   mvn compile exec:java -Dexec.mainClass="cn.lanink.dataconvert.utils.CheckBlockStatesCount" \
     -Ddataconvert.cache.dir="$CACHE"
   # no args = every dat; exit code 0/1. Specific versions: -Dexec.args="582 netease:766"
   # -Dbindata.dir=/path skips downloads; -Ddataconvert.refresh=true re-fetches
   ```
2. **State tag types are part of identity.** Nukkit-MOT hashes states including the
   tag type: `extinguished:0b` and `extinguished:0` are different states
   (`RuntimeBlockStateRidRepair.java` 111–113; `CheckBlockStatesCount.stateKey`).
   When you `set` a state value, copy the suffix from the existing entry or from the
   vanilla palette entry (`get vanilla_palette_XXX.nbt '.blocks[N].states'`).
3. **Empty `states:{}` compounds are legitimate** and matched specially — do not
   remove them.
4. **Order of entries** inside a palette follows Bedrock's FNV-1a 64-bit hash of the
   state (`utils/HashedPaletteComparator.java`). For protocol ≥ 419 the converters sort
   by name+data; don't reorder manually.
5. Palette files are regenerated by the converters (`RuntimeBlockStateConvert`,
   `RuntimeBlockStateConvertOld`), not edited: use `nbt_tool.py` to *inspect, diff,
   verify and make surgical fixes*, then let the gate decide.

## Useful recipes

```bash
T=.agents/skills/minecraft-nbt/scripts/nbt_tool.py
DC=/path/to/DataConvert   # https://github.com/MemoriesOfTime/DataConvert
R=$DC/src/main/resources
CACHE="$(pwd)/.agents/skills/minecraft-nbt/.cache/dataconvert"   # absolute; see top

# How many states / which root kind?
python3 $T info $R/Target_Data/runtime_block_states_2225.dat
python3 $T info $R/Target_Data/vanilla_palette_2225.nbt

# Check alignment for one entry: read its runtimeId, then look up that palette index
python3 $T get $R/Target_Data/runtime_block_states_2225.dat '[1234]' --compact
#   → {data:352s, name:"minecraft:bamboo_hanging_sign", ..., runtimeId:11585, states:{...}}
python3 $T get $R/Target_Data/vanilla_palette_2225.nbt '.blocks[11585]' --compact
#   → same name and byte-for-byte same states (incl. tag types) — that is the invariant

# Find a block by name without decoding everything into context
python3 $T decode $R/Target_Data/vanilla_palette_2225.nbt -o /tmp/vp.snbt --compact
grep -n 'minecraft:pale_oak_log' /tmp/vp.snbt | head

# PMMP canonical file (multi-root): only JSON can hold it
python3 $T decode $R/PMMP_Data/canonical_block_states_818.nbt -o /tmp/canon.json --format json
python3 - <<'EOF'
import json; d = json.load(open('/tmp/canon.json'))
names = {r["tag"]["value"]["name"]["value"] for r in d["roots"]}
print(len(d["roots"]), "roots,", len(names), "distinct names")
EOF

# Surgical fix with type preserved, then the mandatory gate
python3 $T set $R/Target_Data/runtime_block_states_netease_819.dat '[42].states.open_bit' 1b
python3 $T verify $R/Target_Data/runtime_block_states_netease_819.dat --roundtrip
(cd "$DC" && mvn -q compile exec:java \
  -Dexec.mainClass="cn.lanink.dataconvert.utils.CheckBlockStatesCount" -Dexec.args="netease:819" \
  -Ddataconvert.cache.dir="$CACHE")
```

## Format notes specific to these files

* Nukkit writes strings as standard UTF-8 even in big-endian files; the tool reports
  `strings=mutf8` (the Java default when no non-ASCII evidence exists). Block names
  are ASCII, so bytes are identical — ignore the label.
* Nukkit gzips with a parallel gzip; the tool's gzip output has a different header but
  identical payload (`cmp <(gunzip -c a) <(gunzip -c b)`).
* PMMP network files contain no floats, so endianness is immaterial; the tool reports
  `little`, DataConvert reads them as `BIG_ENDIAN` — same bytes.
* DataConvert's own writer (`NBTIO1.writeGZIPCompressed`) exists only because Nukkit's
  stock writer refuses List roots. `nbt_tool.py encode` handles List roots natively.
* Protocol ≤ 407 (`required_block_states`) vs ≥ 419 (`canonical_block_states`) differ
  in root shape — see table above; the converters branch on this
  (`RuntimeBlockStateConvertOld.java` 334–352).

## Converter entry points (for context)

All run with `mvn compile exec:java -Dexec.mainClass=... [-Dexec.args="..."]` from the
DataConvert root (JDK 17, Maven, network for first dependency resolution; no jar is
built). Main classes live under `cn.lanink.dataconvert`:
`convert.RuntimeBlockStateConvert` (versions hard-coded in `main`),
`convert.RuntimeBlockStateConvertOld` (args: versions, `netease:` prefix),
`utils.CheckBlockStatesCount` (the gate), `convert.RuntimeBlockStateRidRepair`,
`convert.RuntimeBlockStateConnectionExpansion`, `convert.RecipeConvert`,
`convert.item.creative.CreativeItemsJsonConvert`, `utils.DumpLeveldbPalette`.
Config: `nukkitmot.dir`/`NUKKIT_MOT_DIR`, `bindata.dir`/`BIN_DATA_DIR`,
`dataconvert.cache.dir` (default `cache/`; the recipes here always override it to
`$CACHE`), `-Ddataconvert.refresh=true`.
